= RCF Version aktualisieren, Cisco Nexus 9808
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Sie aktualisieren die Version der Referenzkonfigurationsdatei (RCF) auf Ihren Cisco Nexus 9808 Switches, um neue Hardware, eine neue ONTAP Version oder eine neue NX-OS Version in Ihrer AFX 2K-Systemkonfiguration zu unterstützen oder die Konfiguration daran anzupassen.


NOTE: Führen Sie kein Upgrade oder Downgrade Ihrer RCF Version auf eine nicht unterstützte Version durch.

.Bevor Sie beginnen
* Die link:configure-install-upgrade-rcf-overview-9808.html["RCF installieren oder aktualisieren – Übersicht"] Seite muss gelesen worden sein.
* Sie müssen über die serielle Konsole mit den Switches verbunden sein oder grundlegende Konfigurationsinformationen gespeichert haben. Dies ist erforderlich, da das RCF-Upgrade-Verfahren das Löschen der Switch-Einstellungen und die Durchführung einer grundlegenden Konfiguration erfordert.
* Stellen Sie sicher, dass eine aktuelle Sicherungskopie der Switch Konfiguration vorhanden ist.
* Es sollte sichergestellt sein, dass Ihr Cluster voll funktionsfähig ist, das heißt, dass keine Fehler in den Protokollen oder ähnliche Probleme vorliegen.
* Sie benötigen die aktuelle RCF Version.
* Sie benötigen eine Bootkonfiguration in der RCF, die die gewünschten Boot-Images widerspiegelt.
+
Wenn Sie die Bootkonfiguration ändern müssen, um die aktuellen Boot-Images widerzuspiegeln, müssen Sie dies tun, bevor Sie die RCF erneut anwenden, damit bei zukünftigen Neustarts die richtige Version instanziiert wird.



.Informationen zu diesem Vorgang
* Das Upgrade des RCF auf beiden Switches ist ein unterbrechungsfreier Vorgang.
+
** Für dieses Verfahren ist keine operative Inter-Switch-Verbindung (ISL) erforderlich. Dies ist beabsichtigt, da Änderungen der RCF-Version die ISL-Konnektivität vorübergehend beeinträchtigen können. Um einen unterbrechungsfreien Clusterbetrieb zu gewährleisten, werden im Rahmen dieses Verfahrens alle Cluster-LIFs auf den operativen Partner Switch migriert, während die Schritte auf dem Ziel Switch ausgeführt werden.
** Bei diesem Verfahren wird zunächst das RCF auf dem ersten Switch (cs1) aktualisiert und anschließend werden die Schritte für den zweiten Switch (cs2) wiederholt.


* Für dieses Verfahren werden ONTAP-Befehle und Cisco Nexus 9000 Series Switches Befehle benötigt, die einzelnen Schritte geben an, welche CLI zur Eingabe der Befehle verwendet wird.
* Die Beispiele in diesem Verfahren verwenden die folgende Schalter- und Knotennomenklatur:
+
** Die Namen der beiden Cisco Switches lauten cs1 und cs2.
** Die Knotennamen sind node1-01, node1-02, node1-03 und node1-04.
** Die Cluster-LIF-Namen sind:
+
*** node1-01_clus1 und node1-01_clus2 für node1-01
*** node1-02_clus1 und node1-02_clus2 für node1-02
*** node1-03_clus1 und node1-03_clus2 für node1-03
*** node1-04_clus1 und node1-04_clus2 für node1-04


** Der `cluster1::*>` Die Eingabeaufforderung zeigt den Namen des Clusters an.

[[step-2-configure-ports]]
== Schritt 2: Ports konfigurieren

. Mithilfe der Switch-CLI auf Switch cs1 werden die Ports abgeschaltet, die mit allen Ports der Knoten für jede Linecard verbunden sind.
+
Das folgende Beispiel zeigt die Befehle zum Abschalten aller Ports auf Leitungskarte 1 `e1`, `e1-1/1-18`, `e1/19/1-4`, `e1/20/1-4` ......... `e1/35/1-4`. Die Befehle sind für jede Leitungskarte am Switch zu wiederholen.

+
[listing, subs="+quotes"]
----
cs1# *config terminal*
Enter configuration commands, one per line. End with CNTL/Z.
cs1(config)# *interface e1/1-18*
cs1(config-if-range)# *shutdown*
cs1(config)# *interface e1/19/1-4,e1/20/1-4,e1/21/1-4,e1/22/1-4,e1/23/1-4,e1/24/1-4,e1/25/1-4,e1/26/1-4,e1/27/1-4,e1/28/1-4,e1/29/1-4,e1/30/1-4,e1/31/1-4,e1/32/1-4,e1/33/1-4,e1/34/1-4,e1/35/1-4*
cs1(config-if-range)# *shutdown*
cs1(config-if-range)# *exit*
cs1(config)# *exit*
----
+

CAUTION: Stellen Sie sicher, dass Sie *alle* angeschlossenen Ports herunterfahren, um Netzwerkverbindungsprobleme zu vermeiden. Weitere Einzelheiten finden Sie im Knowledge Base Artikel link:https://kb.netapp.com/on-prem/ontap/OHW/OHW-KBs/Node_out_of_quorum_when_migrating_cluster_lif_during_switch_OS_upgrade["Knoten außerhalb des Quorums bei Migration des Cluster-LIF während des Switch-OS-Upgrades"^].

. Falls dies noch nicht erfolgt ist, kann mithilfe der Switch-CLI eine Kopie der aktuellen Switch-Konfiguration gespeichert werden, indem die Ausgabe des folgenden Befehls in eine Textdatei kopiert wird:

+

. Speichern Sie die grundlegenden Konfigurationsdetails in der `write_erase.cfg` Datei auf dem Bootflash.
+
[NOTE]
====
Stellen Sie sicher, dass Sie Folgendes konfigurieren:

** Benutzername und Passwort
** Verwaltungs-IP-Adresse
** Standardgateway
** Schaltername


====
+
[CAUTION]
====
Falls die  `write_erase.cfg` Datei bereits existiert, sollte sie in  `write_erase_old.cfg` wie folgt umbenannt werden:

`cs1# move bootflash:write_erase.cfg write_erase_old.cfg`

====
+
`cs1# show run | i "username admin password" > bootflash:write_erase.cfg`

+
`cs1# show run | section "vrf context management" >> bootflash:write_erase.cfg`

+
`cs1# show run | section "interface mgmt0" >> bootflash:write_erase.cfg`

+
`cs1# show run | section "switchname" >> bootflash:write_erase.cfg`

+
Weitere Einzelheiten finden Sie im Knowledge Base Artikel link:https://kb.netapp.com/on-prem/Switches/Cisco-KBs/How_to_clear_configuration_on_a_Cisco_interconnect_switch_while_retaining_remote_connectivity["Wie man die Konfiguration eines Cisco Interconnect-Switches löscht und gleichzeitig die Remote-Konnektivität beibehält"^].

. Mit der Switch-CLI lässt sich überprüfen, ob die  `write_erase.cfg` Datei wie erwartet gefüllt ist:
+
`show file bootflash:write_erase.cfg`

. Mit der CLI des Switches wird der  `write erase`-Befehl ausgeführt, um die aktuell gespeicherte Konfiguration zu löschen:
+
`cs1# *write erase*`

+
`Warning: This command will erase the startup-configuration.`

+
`Do you wish to proceed anyway? (y/n)  [n] *y*`

. Mit der Switch-CLI wird die zuvor gespeicherte Basiskonfiguration in die Startkonfiguration kopiert.
+
`cs1# *copy bootflash:write_erase.cfg startup-config*`

. Der Switch wird mithilfe der Switch-CLI neu gestartet:
+
`cs1# *reload*`

+
`This command will reboot the system. (y/n)?  [n] *y*`

. Sobald die Management-IP-Adresse wieder erreichbar ist, melden Sie sich über SSH am Switch an.
+
Möglicherweise müssen Sie die Einträge in der Host-Datei aktualisieren, die mit den SSH-Schlüsseln zusammenhängen.
