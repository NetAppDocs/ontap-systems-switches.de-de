= NX-OS auf dem Cisco Nexus 9808 Switch aktualisieren
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Das NX-OS auf Cisco Nexus 9808 Switches wird aktualisiert, um neue Hardware oder eine neue ONTAP Version auf AFX 2K Systemen zu unterstützen.


NOTE: NetApp empfiehlt, zunächst ein ONTAP Software-Upgrade abzuschließen und anschließend das Software-Upgrade für Ihre Switches durchzuführen.

.Bevor Sie beginnen
* Stellen Sie sicher, dass eine aktuelle Sicherungskopie der Switch Konfiguration vorhanden ist.
* Es sollte sichergestellt sein, dass Ihr Cluster voll funktionsfähig ist, das heißt, dass keine Fehler in den Protokollen oder ähnliche Probleme vorliegen.


.Informationen zu diesem Vorgang
* Bei Bedarf kann auf die link:https://www.cisco.com/c/en/us/td/docs/dcn/nx-os/nexus9000/101x/upgrade/cisco-nexus-9000-nx-os-software-upgrade-downgrade-guide-101x.html["Leitfaden für Software-Upgrades und -Downgrades der Cisco Nexus 9000-Serie mit NX-OS"^] für weitere Informationen verwiesen werden.
* Bei Bedarf kann auf die link:https://www.cisco.com/c/dam/en/us/td/docs/dcn/tools/nexus-9k3k-issu-matrix/index.html["Cisco Nexus 9000 und 3000 Upgrade- und ISSU-Matrix"^] verwiesen werden, die Informationen zum In-Service Software Upgrade (ISSU) für Cisco Nexus 9000 Series Switches auf Basis der aktuellen und Zielversionen enthält.
+
Wählen Sie auf der Seite *Disruptives Upgrade* aus und wählen Sie Ihre aktuelle Version und die Zielversion aus der Dropdown-Liste.

* Die auf Ihrem AFX-System ausgeführte ONTAP-Version bestimmt die unterstützten Versionen von NX-OS für Ihre Switches.
+
** Für Switches in einem AFX 2K-System, auf denen ONTAP 9.19.1GA oder höher ausgeführt wird, wird NX-OS 10.6 und höher unterstützt.
+
Die aktuelle Liste der unterstützten NX-OS Versionen befindet sich auf der link:https://mysupport.netapp.com/site/info/cisco-ethernet-switch["NetApp Cisco Ethernet-Switches"^] Seite.

+

NOTE: Führen Sie kein Upgrade oder Downgrade Ihrer NX-OS Version auf eine nicht unterstützte Version durch.



* Da für dieses Verfahren ONTAP-Befehle und Cisco Nexus 9000 Series Switches Befehle benötigt werden, geben die Schritte an, welche CLI Sie zur Eingabe der Befehle verwenden.
* Die Beispiele in diesem Verfahren verwenden die folgende Schalter- und Knotennomenklatur:
+
** Die Namen der beiden Cisco Switches lauten cs1 und cs2.
** Die Knotennamen sind node1-01, node1-02, node1-03 und node1-04.
** Die Cluster-LIF-Namen sind:
+
*** node1-01_clus1 und node1-01_clus2 für node1-01
*** node1-02_clus1 und node1-02_clus2 für node1-02
*** node1-03_clus1 und node1-03_clus2 für node1-03
*** node1-04_clus1 und node1-04_clus2 für node1-04


** Der `cluster1::*>` Die Eingabeaufforderung zeigt den Namen des Clusters an.


* Die in diesem Verfahren gezeigten Beispiele gelten für AFX 2K Systeme mit Switches, auf denen RCF 10.1 ausgeführt wird. Die Eingabe und Ausgabe kann je nach Ihrer RCF Version variieren.

== Schritt 1: Vorbereitung auf das NX-OS Upgrade

Das Upgrade von NX-OS wird vorbereitet, indem eine Management-Netzwerkverbindung zu jedem Switch sichergestellt, die NX-OS-Version heruntergeladen, der Portstatus im Cluster überprüft und die automatische Rücksetzung auf den Cluster-LIFs deaktiviert wird.

.Schritte
. Jeder Switch wird mit dem Managementnetzwerk verbunden.
. Mithilfe der Switch-CLI ist die Verbindung zum Server zu überprüfen, auf dem NX-OS gehostet wird:
+
`ping <IP address>`

+
.Beispiel anzeigen
[%collapsible]

. Mithilfe der ONTAP CLI die automatische Rückkehr auf den Cluster-LIFs deaktivieren. Die Cluster-LIFs wechseln auf den Partner-Cluster-Switch und verbleiben dort, während dieses Verfahren auf dem Ziel-Switch durchgeführt wird:
+
[source, cli]
----
network interface modify -vserver Cluster -lif * -auto-revert false
----




[[step-2-install-the-nx-os]]
== Schritt 2: Installation von NX-OS

[[step-3-complete-the-nx-os-upgrade]]
== Schritt 3: Das NX-OS Upgrade abschließen

Mit der ONTAP CLI wird das NX-OS-Upgrade abgeschlossen, indem die automatische Rücksetzung auf den Cluster-LIFs wieder aktiviert und überprüft wird, ob die Cluster-LIFs auf ihre ursprünglichen Ports zurückgekehrt sind.

. Die automatische Wiederherstellung der Cluster LIFs wird wieder aktiviert:
+
[source, cli]
----
network interface modify -vserver Cluster -lif * -auto-revert true
----
. Überprüfen Sie, ob die Cluster-LIFs wieder auf ihren Heimatport zurückgekehrt sind:
+
[source, cli]
----
network interface show -role cluster
----
+
.Beispiel anzeigen

----
