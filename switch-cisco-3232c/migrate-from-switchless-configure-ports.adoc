= Ports für die Migration von einem Zwei-Knoten Cluster ohne Switches zu einem Zwei-Knoten Cluster mit Switches konfigurieren
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Die folgenden Schritte beschreiben die Konfiguration der Ports für die Migration von einem Zwei-Knoten Cluster ohne Switches zu einem Zwei-Knoten Cluster mit Switches auf Nexus 3232C Switches.

.Schritte
. Die LIFs n1_clus1 und n2_clus1 werden auf die physischen Ports ihrer Zielknoten migriert:
+
`network interface migrate -vserver _vserver-name_ -lif _lif-name_ source-node _source-node-name_ -destination-port _destination-port-name_`

+
.Beispiel anzeigen
[%collapsible]
====
Der Befehl ist für jeden lokalen Knoten auszuführen, wie im folgenden Beispiel dargestellt:

[listing, subs="+quotes"]
----
cluster::*> *network interface migrate -vserver cluster -lif n1_clus1 -source-node n1
-destination-node n1 -destination-port e4e*
cluster::*> *network interface migrate -vserver cluster -lif n2_clus1 -source-node n2
-destination-node n2 -destination-port e4e*
----
====
. Es wird überprüft, ob die Cluster-Schnittstellen erfolgreich migriert wurden:
+
`network interface show -role cluster`

+
.Beispiel anzeigen
[%collapsible]
====
Das folgende Beispiel zeigt, dass der Status „Is Home“ für die LIFs n1_clus1 und n2_clus1 nach Abschluss der Migration auf „false“ steht:

[listing, subs="+quotes"]
----
cluster::*> *network interface show -role cluster*
 (network interface show)
            Logical    Status     Network            Current       Current Is
Vserver     Interface  Admin/Oper Address/Mask       Node          Port    Home
----------- ---------- ---------- ------------------ ------------- ------- ----
Cluster
            n1_clus1   up/up      10.10.0.1/24       n1            e4e     false
            n1_clus2   up/up      10.10.0.2/24       n1            e4e     true
            n2_clus1   up/up      10.10.0.3/24       n2            e4e     false
            n2_clus2   up/up      10.10.0.4/24       n2            e4e     true
 4 entries were displayed.
----
====
. Die Cluster-Ports für die LIFs n1_clus1 und n2_clus1, die in Schritt 9 migriert wurden, herunterfahren:
+
`network port modify -node _node-name_ -port _port-name_ -up-admin false`

+
.Beispiel anzeigen
[%collapsible]
====
Der Befehl ist für jeden Port wie im folgenden Beispiel auszuführen:

[listing, subs="+quotes"]
----
cluster::*> *network port modify -node n1 -port e4a -up-admin false*
cluster::*> *network port modify -node n2 -port e4a -up-admin false*
----
====
. Überprüfen Sie die Konnektivität der Remote-Cluster-Schnittstellen:


[role="tabbed-block"]
====

====
. [[step5]] Das Kabel von e4a am Node n1 entfernen.
+
Es kann auf die laufende Konfiguration Bezug genommen und der erste 40 GbE Port am Switch C1 (Port 1/7 in diesem Beispiel) mit e4a an n1 verbunden werden, wobei eine für Nexus 3232C Switches unterstützte Verkabelung verwendet wird.

. Das Kabel von e4a an Node n2 abziehen.
+
Sie können die laufende Konfiguration konsultieren und e4a mit dem nächsten verfügbaren 40 GbE Port auf C1, Port 1/8, unter Verwendung unterstützter Kabel verbinden.

. Alle zum Knoten führenden Ports an C1 aktivieren.
+
Weitere Informationen zu Cisco-Befehlen finden Sie in den in der link:https://www.cisco.com/c/en/us/support/switches/nexus-3000-series-switches/products-command-reference-list.html["Cisco Nexus 3000 Series NX-OS Befehlsreferenzen"^] aufgeführten Anleitungen.

+
.Beispiel anzeigen
[%collapsible]
====
Das folgende Beispiel zeigt, wie die Ports 1 bis 30 auf den Nexus 3232C Cluster Switches C1 und C2 mithilfe der in RCF unterstützten Konfiguration aktiviert werden `NX3232_RCF_v1.0_24p10g_26p100g.txt`:

[listing, subs="+quotes"]
----
C1# *configure*
C1(config)# *int e1/1/1-4,e1/2/1-4,e1/3/1-4,e1/4/1-4,e1/5/1-4,e1/6/1-4,e1/7-30*
C1(config-if-range)# *no shutdown*
C1(config-if-range)# *exit*
C1(config)# *exit*
----
====

`network port modify -node _node-name_ -port _port-name_ -up-admin true`

. Für jeden Knoten sind alle migrierten Cluster Interconnect-LIFs zurückzusetzen:
+
`network interface revert -vserver cluster -lif _lif-name_`

+
.Beispiel anzeigen
[%collapsible]
====
Jeder LIF muss einzeln auf seinen Heimatport zurückgeführt werden, wie im folgenden Beispiel dargestellt:

[listing, subs="+quotes"]
----
cluster::*> *network interface revert -vserver cluster -lif n1_clus1*
cluster::*> *network interface revert -vserver cluster -lif n2_clus1*
----
====
. Es wird überprüft, ob alle LIFs nun wieder auf ihre ursprünglichen Ports zurückgesetzt wurden:
+
`network interface show -role cluster`

+
Die Spalte `Is Home` sollte für alle in der Spalte `Current Port` aufgelisteten Ports einen Wert von `true` anzeigen. Wenn der angezeigte Wert `false` ist, wurde der Port nicht zurückgesetzt.

+
`network interface migrate cluster -lif _lif-name_ -source-node _source-node-name_ -destination-node _destination-node-name_ -destination-port _destination-port-name_`

.Beispiel anzeigen

. Das Kabel von e4e am Node n1 abziehen.
+
Es kann auf die laufende Konfiguration Bezug genommen und der erste 40-GbE-Port am Switch C2 (Port 1/7 in diesem Beispiel) mit e4e am Node n1 über die geeignete Verkabelung für das Switch-Modell Nexus 3232C verbunden werden.

. Das Kabel von e4e an Node n2 abziehen.
+
Die laufende Konfiguration kann herangezogen und e4e mit dem nächsten verfügbaren 40 GbE Port auf C2, Port 1/8, unter Verwendung der für das Nexus 3232C Switch-Modell geeigneten Verkabelung verbunden werden.

. Alle zum Knoten führenden Ports auf C2 aktivieren.
+
.Beispiel anzeigen
[%collapsible]
====
Das folgende Beispiel zeigt Ports 1 bis 30, die auf den Nexus 3132Q-V Cluster Switches C1 und C2 mit einer in RCF unterstützten Konfiguration aktiviert werden  `NX3232C_RCF_v1.0_24p10g_26p100g.txt`:

[listing, subs="+quotes"]
----
C2# *configure*
C2(config)# *int e1/1/1-4,e1/2/1-4,e1/3/1-4,e1/4/1-4,e1/5/1-4,e1/6/1-4,e1/7-30*
C2(config-if-range)# *no shutdown*
C2(config-if-range)# *exit*
C2(config)# *exit*
----
====
. Den zweiten Cluster-Port, e4e, auf jedem Knoten aktivieren:
+
`network port modify`

+
.Beispiel anzeigen
[%collapsible]
====
Das folgende Beispiel zeigt, dass der zweite Cluster-Port e4e auf jedem Knoten aktiviert wird:

[listing, subs="+quotes"]
----
cluster::*> *network port modify -node n1 -port e4e -up-admin true*
cluster::*> *network port modify -node n2 -port e4e -up-admin true*s
----
====
. Für jeden Knoten sind alle migrierten Cluster Interconnect-LIFs zurückzusetzen:
+
`network interface revert`

+
.Beispiel anzeigen
[%collapsible]
====
Das folgende Beispiel zeigt, dass die migrierten LIFs auf ihre ursprünglichen Ports zurückgesetzt werden.

[listing, subs="+quotes"]
----
cluster::*> *network interface revert -vserver Cluster -lif n1_clus2*
cluster::*> *network interface revert -vserver Cluster -lif n2_clus2*
----
