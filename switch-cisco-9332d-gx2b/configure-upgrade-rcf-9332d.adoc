= RCF-Version aktualisieren, Cisco Nexus 9332D-GX2B
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Die Version der Referenzkonfigurationsdatei (RCF) auf den Cisco Nexus 9332D-GX2B Switches wird aktualisiert, um neue Hardware, eine neue ONTAP Version oder eine neue NX-OS Version in der AFX 1K oder AFX 2K Systemkonfiguration zu unterstützen oder anzugleichen.


NOTE: Führen Sie kein Upgrade oder Downgrade Ihrer RCF Version auf eine nicht unterstützte Version durch.

.Bevor Sie beginnen
* Die link:configure-install-upgrade-rcf-overview-9332d.html["RCF installieren oder aktualisieren – Übersicht"] Seite muss gelesen worden sein.
* Stellen Sie sicher, dass eine aktuelle Sicherungskopie der Switch Konfiguration vorhanden ist.
* Es sollte sichergestellt sein, dass Ihr Cluster voll funktionsfähig ist, das heißt, dass keine Fehler in den Protokollen oder ähnliche Probleme vorliegen.
* Sie benötigen die aktuelle RCF Version.
* Sie benötigen eine Bootkonfiguration in der RCF, die die gewünschten Boot-Images widerspiegelt.
+
Wenn Sie die Bootkonfiguration ändern müssen, um die aktuellen Boot-Images widerzuspiegeln, müssen Sie dies tun, bevor Sie die RCF erneut anwenden, damit bei zukünftigen Neustarts die richtige Version instanziiert wird.



.Informationen zu diesem Vorgang
* Um einen unterbrechungsfreien Clusterbetrieb zu gewährleisten, werden bei diesem Verfahren alle Cluster-LIFs auf den operativen Partner Switch migriert, während die Schritte auf dem Ziel Switch durchgeführt werden.
* Für diesen Vorgang ist keine operative Inter-Switch-Link (ISL) erforderlich. Dies ist beabsichtigt, da Änderungen der RCF-Version die ISL-Konnektivität vorübergehend beeinträchtigen können.
* Da für dieses Verfahren ONTAP-Befehle und Cisco Nexus 9000 Series Switches Befehle benötigt werden, geben die Schritte an, welche CLI Sie zur Eingabe der Befehle verwenden.
* Die Beispiele in diesem Verfahren verwenden die folgende Schalter- und Knotennomenklatur:
+
** Die Namen der beiden Cisco Switches lauten cs1 und cs2.
** Die Knotennamen sind node1-01, node1-02, node1-03 und node1-04.
** Die Cluster-LIF-Namen sind:
+
*** node1-01_clus1 und node1-01_clus2 für node1-01
*** node1-02_clus1 und node1-02_clus2 für node1-02
*** node1-03_clus1 und node1-03_clus2 für node1-03
*** node1-04_clus1 und node1-04_clus2 für node1-04


** Der `cluster1::*>` Die Eingabeaufforderung zeigt den Namen des Clusters an.


* Die in diesem Verfahren gezeigten Beispiele gelten für AFX 1K Systeme mit Switches, auf denen RCF 10.0 läuft. Bei einem AFX 2K System können die Ein- und Ausgaben abweichen.




[[step-1-prepare-for-the-upgrade]]
== Schritt 1: Vorbereitung auf das Upgrade

. Wenn AutoSupport auf diesem Cluster aktiviert ist, unterdrücken Sie die automatische Fallerstellung durch Aufruf einer AutoSupport -Nachricht:
+
[source, cli]

[[step-2-upgrade-the-rcf]]
== Schritt 2: RCF aktualisieren

Für das RCF-Upgrade werden die Switch-CLI und die ONTAP-CLI verwendet (wie in den folgenden Schritten angegeben). Das RCF wird auf dem ersten Switch (cs1) aktualisiert, anschließend werden diese Schritte für den zweiten Switch (cs2) wiederholt.

. Mithilfe der Switch-CLI auf Switch cs1 werden die Ports abgeschaltet, die mit allen Ports der Nodes verbunden sind.
+

CAUTION: Stellen Sie sicher, dass Sie *alle* angeschlossenen Ports herunterfahren, um Netzwerkverbindungsprobleme zu vermeiden. Siehe den Knowledge Base Artikel https://kb.netapp.com/on-prem/ontap/OHW/OHW-KBs/Node_out_of_quorum_when_migrating_cluster_lif_during_switch_OS_upgrade["Knoten außerhalb des Quorums bei Migration des Cluster-LIF während des Switch-OS-Upgrades"^] für weitere Details.

+
[listing, subs="+quotes"]
----
cs1# *config*
cs1(config)# *interface e1/1/1-4,e1/2/1-4,e1/3/1-4,e1/4/1-4,e1/5/1-4,e1/6/1-4,e1/7/1-4,e1/8/1-4*
cs1(config-if-range)# *shutdown*
cs1(config)# *interface e1/9/1-4,e1/10/1-4,e1/11/1-4,e1/12/1-4,e1/13/1-4,e1/14/1-4,e1/15/1-4,e1/16/1-4*
cs1(config-if-range)# *shutdown*
cs1(config)# *interface e1/17/1-4,e1/18/1-4,e1/19/1-4,e1/20/1-4,e1/21/1-4,e1/22/1-4,e1/23/1-4*
cs1(config-if-range)# *shutdown*
cs1(config)# *interface e1/24/1-4,e1/25/1-4,e1/26/1-4,e1/27/1-4,e1/28/1-4,e1/29/1-4,e1/30/1-4*
cs1(config-if-range)# *shutdown*
cs1(config-if-range)# *exit*
cs1(config)# *exit*

====
+
`cs1# show run | i "username admin password" > bootflash:write_erase.cfg`

+
`cs1# show run | section "vrf context management" >> bootflash:write_erase.cfg`

+
`cs1# show run | section "interface mgmt0" >> bootflash:write_erase.cfg`

+
`cs1# show run | section "switchname" >> bootflash:write_erase.cfg`

+
`cs1# echo "hardware access-list tcam region ing-racl 1024" >> bootflash:write_erase.cfg`

+
`cs1# echo "hardware access-list tcam region egr-racl 1024" >> bootflash:write_erase.cfg`

+
`cs1# echo "hardware access-list tcam region ing-l2-qos 1536" >> bootflash:write_erase.cfg`

+
Weitere Einzelheiten finden Sie im Knowledge Base Artikel link:https://kb.netapp.com/on-prem/Switches/Cisco-KBs/How_to_clear_configuration_on_a_Cisco_interconnect_switch_while_retaining_remote_connectivity["Wie man die Konfiguration eines Cisco Interconnect-Switches löscht und gleichzeitig die Remote-Konnektivität beibehält"^].

. Mit der Switch-CLI lässt sich überprüfen, ob die  `write_erase.cfg` Datei wie erwartet gefüllt ist:
+
`show file bootflash:write_erase.cfg`

. Mit der Switch-CLI die aktuell gespeicherte Konfiguration löschen:
+
`write erase`

+
`Warning: This command will erase the startup-configuration.`

+
`Do you wish to proceed anyway? (y/n)  [n] *y*`

. Mithilfe der Switch-CLI wird die zuvor gespeicherte Basiskonfiguration in die Startkonfiguration kopiert:
+
`copy bootflash:write_erase.cfg startup-config`

. Der Switch wird mithilfe der Switch-CLI neu gestartet:
+
`reload`

+
`This command will reboot the system. (y/n)?  [n] *y*`

. Sobald die Management-IP-Adresse wieder erreichbar ist, melden Sie sich über SSH am Switch an.
+
Möglicherweise müssen Sie die Einträge in der Host-Datei aktualisieren, die mit den SSH-Schlüsseln zusammenhängen.

. Mithilfe der Switch-CLI wird die RCF-Datei mit einem der folgenden Übertragungsprotokolle in den Bootflash von Switch cs1 kopiert: FTP, TFTP, SFTP oder SCP.
+
Weitere Informationen zu Cisco-Befehlen finden Sie im entsprechenden Leitfaden in der link:https://www.cisco.com/c/en/us/td/docs/dcn/nx-os/nexus9000/102x/command-reference/config/b_n9k_config_commands_1021.html["Cisco Nexus 9000 Serie NX-OS Befehlsreferenz"^].

`copy <protocol>: bootflash: vrf management`
